## 修复：手部动捕「握不了拳 / 手只能前后晃 / 与显示不符」

用户反馈原话：手掌只能前后晃动、握拳握不了、手指与显示不符、不能一比一还原。
排查出 6 个独立缺陷，逐个修掉：

1. **手指弯曲度公式严重低估**（`motion_capture._finger_curl`）
   原来 `(180 - PIP夹角) / 180`：真实握拳 PIP 夹角约 75°，换算只有 0.58，
   怎么握都握不紧。改成以**指节伸展比**为主判据
   （`(chain - dist(mcp,dip)) / (chain * 0.36)`，握拳时指尖折回掌心，比值掉得最快），
   PIP 夹角做辅助，两者取 max。现在张开 0.0、握拳 1.0，单调。
2. **几何量误用归一化坐标**：归一化把 x、y 按画面宽高分别缩放，夹角整体失真
   （自检实测半握时伸展度差异 0.341）。`_hands_to_drive` / `_wrist_roll` /
   `_update_gestures` 全部改用 `_hand_points`（像素坐标），
   只有手腕左右/上下位置继续用 `_hand_norm`。
3. **Live2D 手指参数静息位被拉到底**：`_write_param` 原来按**整段量程**线性映射，
   参数范围 -1..1 默认 0 时，张手会把手指写到 -1（过度伸直），握拳只到量程一小部分。
   改成**以 default 为静息锚点**：signed 时 0 → default、±1 → 两侧极端；
   unit 时 0 → default、1 → 数值更大的一端（新增 `unit_low` 走另一端）。
4. **syHand 系列没有侧摆参数 → 左右移动手掌完全没反应**：
   该系列每臂只有 syHand1（上臂旋转）一个参数。`_apply_arm` 现在在无 `arm_b` 时
   把侧摆按 0.45 权重并进上臂旋转（抬落 0.78），左右移动能带出动作。
5. **手旋转参数被侧摆占用**：`ParamHandLB/RB` 是「手旋转」，原来按侧摆驱动；
   现在 `_ensure_hand_binding` 把它绑到 `wrist`（和 syHand3 同类），跟掌心横轴 roll 走。
   同时新增逐指参数探测（`ParamFinger*`），有逐指参数的模型才能逐指还原。
6. **手离开画面后手指卡住**：`_extract_drive` 默认字典没补 `finger_*` / `wrist_*`，
   而 VRM 的 `set_drive` 只更新传进来的键 → 手放下后手指保持上一个姿势。
   现在补齐 18 个手部键并全部归零。

连带修掉：
- `settings_store.load_motion` 只做浅合并，老配置里的 `motion.params` 会把默认值整块顶掉，
  后加的手部倍率（hand_l / arm_l_x / wrist_l…）读不到，参数面板里对应的滑条根本不出现。
  新增 `_merge_motion()` 做逐层合并（params / gesture_actions）。
- Live2D 手指「反转」开关原本失效（负值在 `_apply_arm` 里被 `_clamp(..., 0, 1)` 夹成 0）。
  改用符号决定写向参数的哪一端。
- `_ensure_hand_binding` 里 `if self._param_meta: self._ensure_param_meta()` 是反向判断（死代码），
  改为无条件调用。
- VRM 右臂肘部弯曲误用左臂信号（`flex` 用了 `al`）；手指每节只给 55°×系数导致弯不到拳，
  改为 MCP 85° / PIP 75° / DIP 50°。
- 手部检测抽帧默认从 2 帧改为每帧，并新增设置项 `hand_every`（UI：动捕页「跟手速度」下拉）。
- 指令台画面在每只手旁边画五根手指的弯曲度柱状图，便于肉眼核对识别是否准。

**Live2D 能力边界（要写进论文/答辩）**：常见模型每条手臂只有一个「手指」参数，
无法逐指还原，只能整体张开/握起；要逐指还原需带 `ParamFinger*` 的模型或改用 VRM。
`材料/` 里 4 个模型的参数清单已确认：hiyori_pro 有 `ParamArmLA/LB`、`ParamHandL/LB`；
云吞kumo / nekoN圣诞小裙子 / 玳瑁猫 都是 `syHand1..5{L,R}`。

## 修复：VRM 胳膊「只能伸直和放下，不能像现实一样弯曲旋转」

用户反馈原话：vrm 的胳膊动捕有问题，现在胳膊只能伸直和放下，不能像现实一样弯曲旋转。

### 排查出的三个独立缺陷

1. **肘部的 delta 漏了「世界旋转 → 骨骼局部坐标系」的换算。**
   `_apply_drive` 里写的是 `_pose_delta[node] = _to4(_axis_rot(world_axis, deg))`，
   而 glTF 的局部矩阵要乘在 `base_local` **右边**，世界旋转必须先做
   `restᵀ · R · rest`。少了这一步，130° 的驱动就变成绕小臂**自身长轴**的扭转：
   下臂的世界旋转确实变了 130°，手腕却只挪了 0.014（预期 0.40）。
   现在统一走 `VRMRig._drive_bone()`。

2. **按 T-pose 假设写死了 `_rz(70)`。**
   实测两个模型的绑定姿态完全不同：AliciaSolid 是标准 T-pose（手臂沿 ±X 水平伸出），
   Seed-san 的手臂朝 +Z 前伸。写死的 70° 对前者勉强凑合（从水平到下垂正好约 72°），
   对后者是乱转。现在 `VRMRig._anatomy()` 从模型的**静息骨骼位置**量出左右轴、
   前后轴、上臂/前臂方向，并用 `_rotation_between()` 算出把绑定姿态摆到"自然下垂"
   的基准旋转（AliciaSolid 71.7°、Seed-san 94.8°）。

3. **肘弯只随 `arm_l`（手在画面里的高度）变化，且被写死成 20°+25°×抬手量。**
   `arm_l` / `arm_l_x` 本质是手在画面里的归一化位置，给不了关节角。
   `MotionCapture._apply_arms_ik()` 换成**二维两杆 IK**：由肩-腕距离定肘弯、
   肩→肘方向定上臂摆角，输出新的度数量 `arm_swing_l/r`、`elbow_l/r`。

## 修复：VRM「胳膊一抽一抽 / 手臂贴在肚子上 / 手指撇到外翻一圈」

用户反馈原话：「模型不够精细，总感觉控制有问题，模型胳膊一抽一抽的，如何贴近真实，
手出现手臂不能在肚子上吧，手指都能撇到外翻一圈，这能对吗」。三个独立问题。

### 1. 手指外翻（`rig.py`）

根因：旧代码让**每根指骨绕自己的局部 Z 轴**转 `_axis_rot((0,0,1), curl*角度)`。
各指骨的局部坐标系朝向互不相同——探针实测 AliciaSolid 手掌朝下、指骨沿 -X、
弯曲轴应取 +Z；Seed-san 手臂前伸、指骨沿 +Z、弯曲轴应取 -Y。绕固定局部轴转，
对一部分指骨就是"绕手背/侧面拧"，看起来就是外翻一圈。

新做法（`VRMRig._finger_axes()`，结果缓存）：
- 从静息姿态量出**掌心方向** `flex`：取 腕→中指根 与 食指根→小指根 叉乘得掌法线，
  再让四指各自用「绕轴正转应把指尖折向手腕」定号（`_orient`），四指求和取共识；
  拇指沿用它（拇指自己那一票会翻）。
- 每根指骨的弯曲轴 = `指骨方向 × flex`，正角度一定折向掌心。绕轴由
  `_drive_bone` 换算进骨骼局部坐标系，所以会跟着上臂/父指骨一起转。
- 拇指只驱动 `Proximal` / `Distal`（`Metacarpal` 在掌心内，转了整根拇指会掀出来）。
- 角度改为 近节 85° / 中节 90° / 远节 55°，拇指 50°/50°。

### 2. 手臂贴到肚子上（`motion_capture` + `rig`）

三个原因，逐个修：

- **肘位两解挑错了**。原来只按「屏幕 y 更大（更靠下）」挑。手一伸到身体中线附近
  （摸肚子、抱胸），那个解会把肘放到身体的**另一侧**，看着就是胳膊压在肚子上。
  改成**外侧优先**：先比肘相对肩的外侧偏移量，只在两者明显打平（±2% 臂长，此时
  手臂接近伸直、两解本来就重合）时才用"更靠下"当次判据。
- **肘弯能折到 150°（几乎反关节）**。给肩腕距离加下限
  `_MIN_ARM_RATIO = 0.42 × 臂长` → 肘弯上限 ≈ 130°，再叠一道 `_MAX_ELBOW = 132`。
  实测"手收到胸前"从 150° 变成 130.3°（旧表里那行 150.0° 已过期）。
- **单目看不到深度**：手在画面里落在躯干轮廓内时，真实手臂一定在身体**前方**，
  但模型的手臂停在躯干那一层深度上 → 插进肚子。新增驱动键 `arm_fwd_l/r`
  （整臂前倾/肩前屈，度），由「手离身体中线多近 × 在肩以下多深」估出。
  细节：整臂前倾 φ 后画面竖直投影会缩成 `cos φ`，所以先把目标竖直距离
  反向放大 `1/cos φ` 再解 IK，倾完正好落回用户手的位置（这条不做，补深度会顺带
  把手的高度带偏）。前倾角还要按可达性封顶：需要的手臂长度是
  `√(dx² + dy²(1+tan²φ)·…)`，把 `(1+sin²φ)/cos²φ = 1+2tan²φ` 代进去反解得
  `tanφ_max = √((reach² - d²)/(2dy²))`（`_limit_tilt`）。

### 3. 一抽一抽（`motion_capture`）

四个来源，逐个压掉：

- **丢手就归零**：`_wrist_point` 返回 None 时原来立刻把 `arm_swing/elbow` 清零，
  手每丢一次手臂就从当前姿势抽回自然下垂、再出现又抽回去。现在先**保持上一帧的
  解 18 帧**（`_WRIST_HOLD_FRAMES`），超过再平滑松开。
- **两条映射来回切**：`_last_pose` 一为 None，手臂就切到 `_arms_from_screen`
  （拿画面中心当肩、只看得见手的方向）——两条路解出的角度差很远，YOLO 漏一帧就跳。
  现在 YOLO 连漏 4 次（`_POSE_HOLD_RUNS`）才清空缓存。
- **手部/YOLO 腕点来回切**：MediaPipe 丢一两帧就退回 YOLO 腕点，两者系统性地差一段
  距离。新增 `_wrist_mem`（每侧最近的手部腕位 + 帧号），4 帧内沿用手部结果。
- **±180° 绕圈**：肘正好竖直时 `atan2` 换算出的 swing 会差 360°（+180 与 -180
  物理上等价，但 clamp 之后一个变成"举过头"、一个变成"横在身前"）。
  新增 `_unwrap()`，把角度绕到离上一帧平滑值最近的那一支。
- **平滑改成自适应**（`_smooth_value(..., react=)`）：按帧间变化量调增益，
  小变化（噪声）gain=0.10、大变化 gain=0.70，实测手腕 ±3px 抖动传不到摆角
  （波动 0.47°），而真实抬手 6 帧内跟到 100%。

### 新增的回归断言（`vrm_arm_selftest.py` 增 56 项）

- `run_fingers()`：弯曲轴⊥指骨（|cos|<0.05）、绕轴正转指尖折向**掌心**
  （掌侧方向用**拇指相对掌平面的偏移**独立判定，与实现的"四指共识"互为旁证，
  实测 cos 0.85~0.999）、相邻手指轴平行（|cos|>0.9，各指各轴就是外翻）、
  端到端屈指后指尖到手腕距离必须变小（实测 0.098→0.047）。
- `test_belly_and_elbow()`：手在肚子前时肘弯 ≤133、前倾 >12°、越靠中线前倾越多、
  手在身上侧不前倾；再把 IK 解喂给骨骼，断言**肘留在肩同侧**（不越过中线）且
  手被摆到模型正面（沿 `_anatomy()['fwd']` 分量 >0.1）。
- `test_stability()`：±3px 抖动、丢手后先保持再松开且无台阶、`_unwrap` 的
  ±180 取支、真实动作的跟随速度、自适应平滑的慢跟/快跟。

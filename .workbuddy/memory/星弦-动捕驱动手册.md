# 星弦 · 动捕与骨骼驱动手册（详细笔记）

> `MEMORY.md` 是精简索引，这份是展开的细节。改 `motion_capture` / `rig` / 视图
> 驱动链之前先读对应小节。

## 一、驱动链路与手势菜单

- 驱动链：`MotionCapture.drive_changed(dict)` →（Qt 队列信号，UI 线程）→
  `Live2DView.apply_drive(**drive)` / `VRMView.set_drive_params(**drive)`。
  `apply_drive` 是**全量**写参数，任何只改局部（如只改嘴）的调用必须另提供
  只写局部参数的方法。
- 动捕驱动键：`angle_x/y/z`、`body_angle_x/y`、`eye_x/y`、`eye_open_l/r`、
  `mouth_open`、`mouth_form`、`arm_l/r`、`arm_l_x/r_x`、`hand_l/r`、`wrist_l/r`、
  `finger_{l,r}_0..4`、`thigh_*`、`knee_*`，以及 VRM 骨骼专用（度）
  `arm_swing_l/r`（上臂摆动，0=自然下垂）、`elbow_l/r`（肘弯，0=伸直）、
  `arm_fwd_l/r`（整臂前倾，0=不前倾）。新增键要同步改七处：
  `motion_capture._extract_drive` 默认字典、`_apply_drive_params` 倍率表、
  `_swap_lr` 交换表、`DEFAULT_MOTION_SETTINGS["params"]`、`vrm_view._detect_params`、
  `home_window` 驱动数值卡片、`rig._default_drive`。
- 手部驱动键必须在 `_extract_drive` 默认字典里备齐并归零（共 24 个：
  arm_* ×4 + arm_swing_* ×2 + elbow_* ×2 + arm_fwd_* ×2 + finger_* ×10 +
  hand_* ×2 + wrist_* ×2），否则手离开画面时手指会卡在上一帧姿势。
- **纯几何量（手指弯曲度、关节夹角、手腕 roll）一律用像素坐标算**
  （`MotionCapture._hand_points`）：归一化坐标把 x、y 按画面宽高分别缩放，
  夹角和长度比会整体失真。归一化坐标只用于算手腕在画面里的左右/上下位置。
- 手势动作菜单**按模型能力动态生成**，别再写死列表。
  `app/services/model_actions.py` 是**纯函数**（不碰 OpenGL，可无 GPU 单测）：
  动作 id 只有 `none` / `motion:<真名>` / `expression:<真名>`；
  `LEGACY_ACTION_MAP` 把旧 id 映射成*候选真实名列表*。
  Live2D 能力有两个来源**缺一不可**：`.model3.json` 的
  `FileReferences.Motions/Expressions` + 同目录散落的 `*.motion3.json`/`*.exp3.json`
  （VTS 导出的模型一个都不登记）；磁盘扫描**只在 model3.json 未登记该类资源时才做**
  （hiyori 把 10 个 motion 登记成 7 个组，再按文件名扫会造出 `hiyori_m01` 这类假组）。
  功能开关与情绪表情分开：情绪显示「表情：」，开关显示「切换：」。
- `live2d_view._register_extra_assets()` 在**模型加载成功后、makeCurrent 上下文里**
  用 `LoadExtraExpression`/`LoadExtraMotion` 补注册（live2d-py v3）。
  `LoadExtraMotion` 返回实际加载条数，**只有 > 0 才算成功**；加完必须
  `model._motions_cache = None`；`available_actions()` 只报**注册成功**的资源。
- `vrm_view.play_motion()` 是**定时器驱动的骨骼动画**，`set_drive_params` 走
  `_merged_drive()` 让动画层**压过动捕**（旧实现只 set 一次，下一帧就被全量覆盖）。
  动作首尾必须被 `_envelope` 压到 0。
- `home_window._rebuild_gesture_menus()` 在模型加载成功与类型切换时重建下拉框并迁移
  失效映射；解析出的旧 id 要**规范化成前缀形式**。两条红线：用户显式选的「不响应」
  要保留；**模型未加载时绝不改写已存映射**。

## 二、手势识别（`app/services/gesture.py`）

- 纯几何规则法，消费 MediaPipe HandLandmarker 的 21 点。**必须同时吃
  `hand_world_landmarks`（米制 3D）**：单目 2D 投影在「手指正对摄像头」时会把伸出的
  食指压成一小段、且四指投影重叠，`count` 完全不可信。`classify(points, world)`
  用 world 算夹角与距离，world 缺失才退回 2D。
- 拇指「张开」**不能**用拇指自己的指节夹角：握拳时拇指常常是**直的**（只是搭在四指
  上），IP 夹角接近 180° 会把握拳读成点赞。正确判据是「拇指尖离食指近端指骨有多远」
  ——拇指尖到线段 (5→6) / (9→10) 的点-线段距离 ÷ 手掌尺度（腕→中指 MCP），再与 IP
  伸直度取 min。握拳 ≈0.2、点赞 ≈0.8。
- 判据顺序：ok → thumb_up → open_palm → fist → peace → rock → point。
- **绝对阈值有死区，`count==0` 前要过一遍「相对判据」**：指节状态落在
  `_CURLED_DEG`~`_STRAIGHT_DEG`（115°~145° → 状态 0.35~0.6）之间时既不算伸直也不算
  弯曲；四指全落进去就数出 `count==0` → 直接判**握拳**。真实的手做「单指」时食指常
  只伸到 130° 上下，正好落进死区 —— 用户实测「做单指，界面显示握拳」。兜底判据是
  「最直的一根领先第二名多少」（`_SOLO_GAP=0.30`、`_SOLO_MIN=0.35`）：握拳四指齐平
  （领先 0.05），指向时领先 0.47。**反向**也要守住：食指状态 0.167 时必须仍然判握拳。
- 手势去抖在 `motion_capture._update_gestures`：连续 `_gesture_stable_frames` 帧同一
  手势才 emit；手还在画面但判不出手势时**保留已触发状态**，不重复触发。
  ⚠️ 那个保留是给「别重复触发动作」用的，**不是**「当前识别结果」：界面若拿
  `_gesture_active` 显示，就会出现「一直做单指、界面一直显示握拳」。界面要用
  `_hand_shapes`（`MotionCapture.current_hand_shapes()`，每帧覆盖，判不出就是空串），
  状态文字判不出时写「已检测（手型未识别）」。

## 三、手臂动捕（`motion_capture._solve_arm`）

**二维两杆 IK**：肘弯由**肩腕距离**定（不需要肘部关键点，YOLO 肘点质量差）；
上臂朝向由肩→肘方向定。肩腕距离下限 `_MIN_ARM_RATIO = 0.42×臂长`（≈肘弯 130°），
叠 `_MAX_ELBOW = 132`。

### 3.1 肘位挑选：连续插值，**不要再退回硬切**

两支解是「肘在肩腕连线两侧」的镜像，二维看不出深度，只能靠先验挑：

- 先验 A **肘在肩下**（手在肩下方时）：人不可能把手放在胸腹前还把肘举过肩。这条必须
  有——手抬到胸前/肩高附近时手臂弯得厉害（两解分得很开），而「更靠外」那支恰好是把
  肘甩到肩**上方**的解，上臂朝上指 = 「手在下面、模型却在举手」。
- 先验 B **更靠外**（真人的肘在身体外侧）：只按「更靠下」挑的话，手伸到身体中线附近
  会把肘放到身体另一侧，看着就是胳膊压在肚子上。

**关键：不能硬切。** 两条先验互相切换的那一点恰好是「两支解的高度之一与肩同高」，
切换点附近两支解能差上百度的上臂朝向。手在肩线旁边轻轻一动（实测肩外侧抬升
`y=188->184` 一帧跳 43°、越过身体中线抬升跳 93°）上臂就整条翻过去。所以：

- 两个「谁更大」的判断全部换成 `tanh((a-b)/band)` 软判据
  （`_ELBOW_BLEND_BAND = 0.5`，单位 = 上臂长）；
- 再按「分居肩上下 × 手没举过肩」的连续权重把两支解插值。
  姿态分得越开越接近硬选，正好在临界点上平滑过渡。
- 「手没举过肩」是**单侧**斜坡 `raised = clamp(-dy/(0.6×臂长), 0, 1)`：手比肩高几个
  像素不算举手——手越过身体中线伸到对侧肩前时高度正好与肩齐平甚至高几个像素，
  用双侧判据会把这一大类姿势误判成「举手」，让先验 B 挑出「肘抬到肩以上」的解。
- **有可信肘点（YOLO 7/8 号，`_ELBOW_HINT_CONF = 0.50`，到肩距离要落在
  `0.5~1.6×上臂长`）时不走插值**，直接选离它近的解——真测到的位置就是连续数据。
- 手臂折得紧（`reach < 0.6×half`）时，按 `|dy|` 把肘高连续过渡到与肩同高：肘高是
  `sy + a·uy`，`uy` 的符号 = 「手在肩上方还是下方几个像素」，这点差别画面根本分不出，
  但翻号会让上臂从 65° 跳到 99°（手在肩线上下轻微晃动，模型手臂一下一下地弹）。
  与肩同高正是两支镜像解的中点（上臂水平朝外）。

### 3.2 摆角归一化

`atan2` 给的是 **[0°, 360°)**（0=自然下垂、90=水平外、180=正上、270=水平内），
而 `_write_arm` 的钳位是 `[-40, 165]`。

- 先折回 `(-180, 180]`（`if swing > 180: swing -= 360`），否则「自然下垂、肘略偏内侧」
  落在 340° 会被直接夹成 165°（= 举手）。
- 再对「朝上但绕过了 ±180 边界」的负角绕回 `+360`（`if swing < 0 and up_comp > 0`），
  否则手举过头顶解出 -174° 会被钳成 -40°——人做不出的姿势，而且会永久贴住下限。
- **不要再用「离上一帧最近」来绕角**（原 `_unwrap` 就是干这个的，已删）：它拿「上一帧
  **已钳位**的平滑值」当参考，一旦被钳过一次参考值就偏 180° 以上，之后每个角度都被绕到
  错误的一支（实测手举过头顶解出 -210°，再钳成 -40°）。
- 画面 x 增大对应「人的哪一侧」由 YOLO 5/6 号肩点 x 先后直接判定（只有一侧肩时退回按
  镜像开关推）；肩/躯干缓存进 `_last_pose`（坐标统一除以**画面高**）。

### 3.3 折叠兜底：手折在身前

`_ARM_FOLDED_SWING = 8`（垂在身侧、略偏外），权重 = `inner × folded`：

- 「内侧」按**半肩宽**衡量（`max(half_w, 0.2×臂长)`），**不是**按臂长：手移到躯干中线
  （离肩 = 半肩宽）就已经折在身前了。原来除以 `0.35×臂长`，手正好到中线时只算 0.8，
  剩下 20% 仍带着两支解各自的方向，而两支解在跨越肩水平线那一帧能差上百度
  （实测 `3.8° -> 33.4°`）。
- **不能**只因为「手离肩近」就拉回：手抬到肩上方一点点、肘朝侧面抬平同样离肩很近，
  但那条手臂是抬着的，硬拉回会在手划过肩水平线时挖出一个 V 形坑
  （实测 `65° -> 8° -> 115°`）。真正退化的那一小块（`reach→0`）由 3.1 的「肘高抹平」
  处理。

## 四、三维补全与去抖

- 单目缺「手伸向镜头」这一维。手落在躯干轮廓内（离中线近 + 肩以下）时真实手臂一定在
  身体**前方**，不补 `arm_fwd_l/r` 小臂会插进肚子。两条易忘：整臂前倾 φ 后画面竖直投影
  缩成 `cos φ`，解 IK 前要把目标竖直距离**反向放大 `1/cos φ`**；前倾会拉长所需三维臂展，
  超出臂长时 IK 只会把距离夹到上限，所以要按可达性封顶
  （`MotionCapture._limit_tilt`：`tanφ_max = √((reach² - d²)/(2·dy²))`）。
- 手臂「一抽一抽」的来源：①丢手立刻归零 → 改保持 `_WRIST_HOLD_FRAMES` 帧再平滑松开；
  ②`_last_pose` 一为 None 就切 `_arms_from_screen`（另一套映射）→ 改连漏
  `_POSE_HOLD_RUNS` 次才清缓存；③手部腕点与 YOLO 腕点系统性地差一段 → `_wrist_mem`
  记最近腕位沿用几帧；④平滑用 `_smooth_value(key, value, react=…)` **自适应**版本
  （小变化 gain=0.10、大变化 gain=0.70），固定 alpha 只能二选一（要么抖要么飘）。

## 五、只露手 / 只露上半身的尺度来源

**症状**：只露手或只露半边身子时，模型手臂朝天飞。四个坑：

1. `_pose_from_body` **不能要求两侧肩都可信**——只露一侧肩就把整份 pose 作废。现在只要
   **至少一侧肩**，返回 `sides` 标明哪几侧可用，只解看得见的那条手臂；躯干中线由
   「肩到中线 = 半肩宽」反推。
2. 退化路径**绝不能读 `drive["arm_l"]`**：那个量在**手被检测到时恰恰不被填充**
   （`_extract_drive` 只在 `not _hand_detected` 时才调 `_apply_arms`），恒为初值 0.0，
   映射出 swing = (0 + 0.76) × 110 = **83.6° 举手**，且与手在画面哪个角落无关。现在改成
   「画面中心当肩 + 假设臂长」**照样走 `_solve_arm`**，输入换成当帧腕点。
3. **臂长尺度分三层拿**（`_pose_from_body` 的 `torso_src`）：髋可信 → 肩→髋距离；
   髋不可信（只露上半身时 YOLO 会外推一个乱飞的髋坐标，实测 torso 在 0.06~0.97 之间跳）
   → 肩宽 × 1.18；只剩一侧肩 → 标 `default`，再由 `_apply_arms_ik` 用**手部掌骨**换真
   尺子（`_hand_palm_scale()`：`arm_len = 6.0 × 腕→中指掌骨`，手与手臂同深度、比值不受
   远近影响）。不换源的话同一个动作摆角差 25°。
4. `_solve_arm` 的单位方向要用**未裁剪**的 reach 归一化：腕点落在肩上时 reach ≈ 0，除以
   被撑到 `d_min` 的 `d` 会得到零向量 → 肘位坍缩到肩上、摆角被误判成 0（手臂突然垂下）。

## 六、VRM 骨骼驱动（`rig.py`）铁律

1. **绑定姿态逐模型不同，绝不能写死旋转角**：AliciaSolid 是 T-pose，Seed-san 手臂朝
   +Z 前伸。由 `VRMRig._anatomy()` 从**静息骨骼位置**量左/右轴、前/后轴与 `baseline`
   （T-pose≈72°，前伸≈95°）。
2. **世界旋转必须转成骨骼局部坐标系**再乘进 glTF 局部矩阵（`_drive_bone` 内部做
   `restᵀ·R·rest`）。直接当局部用会变成绕骨骼**自身长轴**扭转——肘部只会原地打转。
3. **肘部旋转轴要先换算回绑定姿态那一帧**（`baselineᵀ @ bend_idle`），因为肘的 delta 是在
   「已转过的上臂」下执行的。
4. **手指弯曲轴必须从静息姿态量出**，不能绕骨骼局部轴转（各指骨局部坐标系朝向互不相同）。
   见 `VRMRig._finger_axes()`：量**掌心方向** `flex`，每根指骨弯曲轴 = 指骨方向 × flex。
   拇指只驱动 `Proximal`/`Distal`（`Metacarpal` 在掌心内）。

解剖轴含义：`raise`=上臂抬落轴（从自然下垂抬向正上方）；`bend`=肘轴（小臂朝模型正面折）；
`tilt`=肩前屈轴。三者用 `_orient()` 按「绕轴正向转会把 base 转向 toward」定号，不依赖
模型手性。

**调试注意**：`rig.update()` 之后的 `global_of()` 是「施加驱动后」的姿态，不是绑定姿态；
要读绑定姿态只能用 `rig._rest_global`/`_anatomy()`。要比较就同一驱动状态下都比
`global_of`，或干脆比距离（刚体旋转不变量）。静息帧量出的旋转轴不能直接和驱动帧的骨向量
做点乘（轴是绑定帧的，驱动后手臂已转过 baseline）。

## 七、Live2D 参数与能力边界

- 两种命名都要兼容：Cubism 标准 `ParamArmL*/ParamHandL*/ParamMouthForm` 与中文模型的
  `syHand1..5{L,R}`（上臂/小臂/手腕/手指/其他）；取值范围运行时用 `GetParameter(i)` 读，
  不写死。
- `Live2DView._write_param` 换算**以参数 default 为静息锚点**：`signed` 时 0→default、
  ±1→两侧极端；`unit` 时 0→default、1→数值更大的一端；`unit_low` 走另一端。手指「反转」
  靠传负值（`_apply_arm` 用符号选 unit/unit_low）。
- 手部参数能力边界（模型决定，不是 bug）：

  | 命名 | 上臂 | 手腕 | 手指 |
  | --- | --- | --- | --- |
  | `ParamArmLA/LB`（hiyori_pro） | 抬落 + 侧摆 | `ParamHandLB` | `ParamHandL` 单参数 |
  | `syHand1..5{L,R}`（云吞kumo / nekoN / 玳瑁猫） | 仅 `syHand1` 一个旋转 | `syHand3` | `syHand4` 单参数 |

  → 常见 Live2D 模型**无法逐指还原**，只能整体张开/握起；`syHand` 系列没有侧摆参数，
  程序把侧摆按权重并进上臂旋转。逐指还原需带 `ParamFinger*` 的模型或改用 VRM。

## 八、已知边界（未改）

- `arm_swing` 是单根抬落轴，**表达不了「上臂指向内侧水平」**（手臂横在胸前）。输入落到
  这种方向时下游 `[-40,165]` 钳位只能二选一，在「上臂正好水平」那一点仍有一次跳变。
  实测只在「只露手、假设肩在画面中心、手远在画面另一侧（离肩 3 倍臂长，完全够不着）」
  这种退化输入上出现。
- `arm_swing_*`/`elbow_*`/`arm_fwd_*` **只有 VRM 消费**；`live2d_view` 一个都不读，它只用
  `arm_l`/`arm_l_x`。而 `arm_l`/`arm_r` 在手在画面里时不被更新（恒 0），Live2D 的手臂在
  手出现时会僵在静息位；那个量的量纲 `(肩y - 腕y)/肩宽` 还会饱和到 ±1 之外（手垂在身侧
  实测 -1.775）。

## 九、定位套路（动捕数值问题）

用 `MotionCapture.__new__` 起实例（绕过 `__init__`），逐帧喂腕点/hand_norm，把
「输入几何 → 输出角度」整表打出来——**不要靠肉眼猜**。量化「僵硬」用三个指标：
`max_step`（单帧最大变化）、`flips`（方向反转次数）、`mean_step`。怀疑分支翻支时
直接逐帧扫 `_solve_arm` 的**原始**输出（不经平滑），断裂点会自己跳出来。

## 十、自定义姿势手势（每个模型一套手势列表）

需求：手势动作按模型各存一份；默认手势可删、可加自定义手势；「读取动捕的截图动作
当作该手势，弹出命名保存」。定下来的三条：做同样姿势**自动触发**；**手势列表与
绑定动作都按模型各存一份**；录制内容 = **当前一帧动捕解出的驱动数值**。

### 10.1 `app/services/pose_gesture.py`（纯函数 + 纯状态机，可无 Qt 单测）

- `POSE_KEYS` 共 **24** 个特征键：`arm_swing_{l,r}`(0~180, w2)、`elbow_{l,r}`(0~140, w2)、
  `arm_fwd_{l,r}`(0~60, w1.5)、`arm_{l,r}` / `arm_{l,r}_x` / `wrist_{l,r}`(-1~1, w1)、
  `hand_{l,r}`(0~1, w1)、`finger_{l,r}_0..4`(0~1, w0.5)。
  权重按「有多能代表姿势」定；逐指弯曲度只作辅助（同一姿势下手指难免有差异）。
- `capture(drive)` 只取这些键、缺键补 0、**夹进各自量程**（于是逐维差必落在
  `[-1,1]`，`distance` 天然是 0~1）。
- `distance(a,b) = sqrt(Σ w·d² / Σ w)`，`d = (a-b)/量程`；只比较两边都有的键。
  这样角度（180°）、位置（2）、弯曲度（1）能放在同一把尺子上比。
- 容差：`DEFAULT_TOLERANCE = 0.16`（≈ 上臂 ±29° / 肘 ±22° / 手指 ±0.16），
  区间 `[0.04, 0.35]`。**上限按误触发余量定**：「举右手」vs「举左手」实测 0.394
  （24 维里 12 维全反），压在 0.35 以下左右手就不会互相误触发。
- `is_blank` / 空姿势拒收：没检测到手时录下来的模板 = 「模型不动就触发」的鬼手势，
  在 `make_custom_gesture` 和 `sanitize_row` 两处都要拦。
- `PoseTracker`：连续 `POSE_STABLE_FRAMES=3` 帧命中才上报一次，连续
  `POSE_RELEASE_FRAMES=6` 帧落空才解除；`update(pose, available)` 返回
  `id` / `""`(解除) / `None`(无变化)。放在这里而不是 MotionCapture 里，是为了
  能脱离 Qt 单测（`MotionCapture.__new__` 出来的实例发信号会直接
  `RuntimeError: Signal source has been deleted`，别指望用它测信号）。

### 10.2 接线：为什么必须在 `_apply_drive_params` **之前**

`_extract_drive` 的顺序是 `_apply_arms_ik` → **`_update_pose_gesture`** →
`_apply_drive_params`。两条理由缺一条都会坏：

1. 量程按**原始角度**定。用户把灵敏度倍率调到 2.0，120° → 240° 会被夹回 180°，
   差异被抹平；
2. **录制（`current_pose()`）与匹配必须吃同一份数据**，否则用户改一次倍率，之前录的
   姿势全部对不上。

因此 `_pose_snapshot` 存的是原始 drive，而送给模型的是乘过倍率的那份（两者都断言过）。
可用的判定是 `_gesture_enabled and _hand_enabled and _hand_detected and 非空姿势`——
手不在画面时手臂角度全是初值 0，拿去比会命中「手放下来」那些模板。
`_clear_gestures()`（停动捕 / 关手部检测）里要 `reset()` 并补发 `""`。

⚠️ 这三个开关**必须用 `getattr(self, "_xxx", 中性默认)` 读**，不能裸读：`_extract_drive`
会被自检里 `MotionCapture.__new__` 出来的**裸实例**直接调用（`hand_drive_selftest` 的
`_bare_capture()` 就是），那时这些属性不存在，裸读会当场 `AttributeError`——本轮
`hand_drive_selftest` 就是这么挂的。真实实例永远走 `__init__`，取值不变。
**凡是被 `_extract_drive` 间接调用的方法都得守这条**（`_pose_tracker_or_new()` 是同一个
套路的先例）。`pose_gesture_selftest` 第 7 段末尾有一条「裸实例跑
`_update_pose_gesture` 不许抛异常」的回归断言钉着它。

### 10.3 配置：`gesture_profiles`

```
{"live2d:hiyori_pro": {"gestures": [ {id,name,kind,pose,tolerance,action}, ... ]}}
```

- 模型键 = `类型:名字`（不用路径：重装/换机后路径会变，名字是用户自己起的）。
- **默认手势和自定义手势在同一个列表里**，`kind` 区分；所以「删除默认手势」就是把这个
  id 从列表里去掉，「有哪些手势」只有这一个数据源。
- 没有可归属的模型时用公共档 `FALLBACK_PROFILE_KEY = "__default__"`（一个模型都没
  导入时也得能录）；`rows_for` 依次尝试 模型 key → 公共档 → 内置七条。
- **「存过但是空列表」= 用户主动删光**，`rows_for` 必须原样返回空，不能拿默认值填回去。
- 老字段 `gesture_actions` 降级成**兜底 + 迁移来源**（模型还没加载时没有能力清单可查）。
  `_persist_gesture_rows` 里要**整份替换**而不是 `update`——被删的默认手势必须从映射里
  消失，否则手一比划又会触发它。
- `_merge_motion` 里 `gesture_profiles` 只做清洗（`sanitize_profiles`），不与默认值拼接：
  每个模型内部的 `gestures` 是用户的完整意图。

### 10.4 界面（`home_window.py`）

- 手势网格动态重建：每行 = 名字 + `ArrowComboBox`(动作) + 「×」；下方「＋ 录制自定义
  手势」「恢复默认手势」。`_gesture_rows_cache` 是渲染用的行缓存，`gesture_combos`
  是 id→下拉框映射（自检靠它断言）。
- `_action_for_gesture(id)`：自定义手势读行；默认手势读 `gesture_actions`；**行缓存非空
  但里面没有这个 id = 用户删掉了 = 返回「不响应」**。这条是「删掉就真的没了」的关键，
  只断言列表长度是验不出来的。
- `PoseGestureDialog`：姿势摘要 + 名字 + 宽紧三档（0.10 / 0.16 / 0.24）。
- 「恢复默认」**只补缺失的**默认手势并保留自定义手势（不顺手删用户录的东西）。
- 状态行 `_refresh_gesture_status()` 同时显示内置手型（「左手 比耶」）和自定义姿势
  手势（「自定义 举高高」）——两条链路独立，必须都显示，才知道是哪条在触发。

### 10.5 必踩的坑

1. **Qt 布局项不会随 `setParent(None)` 消失**。重建控件时只 `setParent(None)` +
   `deleteLater()`，旧行仍挂在网格里：重建几次格子从 23 涨到 45→66，行距被撑开、
   控件叠在一起。必须 `grid.removeWidget(widget)` 再删。自检里固化成了
   「格子数 == 行数 × 3」。
2. **迁移结果要在配下拉框之前落盘**。`_action_for_gesture` 对默认手势查的是
   `gesture_actions`，那一刻它还是老 id（`wave`），而菜单里是 `motion:wave`，
   顺序反了 `findData` 失配、界面显示回「不响应」。
3. **被 `_extract_drive` 调到的方法不能裸读只在 `__init__` 赋值的属性**，要
   `getattr(self, "_xxx", 默认)`。`MotionCapture.__new__` 出来的裸实例会直接跑
   `_extract_drive`，裸读当场 `AttributeError`（见 10.2）。脚手架
   `_bare_capture()` 也要把开关显式置位，让契约写明。
4. 顺带：离屏环境 `QFontDatabase.families()` 是 **0**，`tools/preview_motion_page.py`
   渲的 PNG 文字全是方框，只能看结构，不是字体 bug。

### 10.6 距离里为什么要有「单根手指」峰值项（`_PEAK_FINGER_WEIGHT`）

**症状**：录的是单指，之后做单指和握拳都会触发同一个自定义手势。

**根因**：加权 RMS 会被维度数摊薄，而手型是**稀疏**特征。伸出一根食指和握拳
只差一根手指，逐指权重 0.5、总量 24 个维度 —— 实测距离只有 **0.153**，比默认容差
0.16 还小。同理「单指 vs 比耶」也是 0.153。这不是调参问题，是度量本身不适合稀疏特征。

**改法**：`distance()` 取两个量的较大值 —— 加权 RMS、以及
「**单根手指最大差异 × 0.6**」（`_peak_finger_delta` × `_PEAK_FINGER_WEIGHT`）。
系数 0.6 是两个数字量出来的：

| 情形 | 距离 | 与容差的关系 |
| --- | --- | --- |
| 单根手指完全反过来（单指 ↔ 握拳） | 0.60 | > 容差上限 0.35，**任何档位都拦得住** |
| 同一姿势重摆、手指各偏 0.25 | 0.15 | ≤ 标准档 0.16，不会灵敏到触发不了 |

换算关系：**标准档能容忍的单指误差 = 0.16 / 0.6 ≈ 0.27**，松档 0.40。

新增自检：`hand_drive_selftest.test_pose_split`（合成手型 → 真实链路 → 量距离）、
`gesture_selftest` 里同一退化视角下「单指 vs 握拳」的距离必须 > 容差上限。

### 10.7 驱动链路的手指弯曲度也要吃世界坐标

`_hands_to_drive` 里三个量的坐标源是**三个不同理由**，别一刀切：

| 量 | 坐标源 | 为什么 |
| --- | --- | --- |
| 手腕位置 `arm_*`、`arm_*_x` | 归一化 | 只要「在画面里的相对位置」，与分辨率无关 |
| 逐指弯曲度 `finger_*`、`hand_*` | **世界坐标**（缺了才退回像素） | 见下 |
| 手腕 roll `wrist_*` | 像素 | 它要表达「手腕在**画面里**倾斜多少」，本来就是屏幕空间的量 |

弯曲度用像素不够：手正对镜头（三维模型 tilt 85°）时二维投影把卷起的手指压平，
逐指弯曲度只剩 `[0.24, 0.00, 0.24, 0.45]`（**中间那根直接读成「伸直」**），而
「单指」是 `[0.00, 0.00, 0.24, 0.45]` —— 两者几乎一样。这同时坏掉两件事：
姿势特征分不开单指和握拳（用户报的 bug），以及模型的手指跟着乱动。世界坐标给的是
`[1,1,1,1]` / `[0,1,1,1]`，分得开。

**注意这是对「用像素算纯几何量」那条红线的补充，不是推翻**：红线反对的是**归一化
坐标**（x、y 按画面宽高分别缩放 → 夹角和长度比整体失真）；世界坐标是米制三维，
比像素更好。

### 10.8 让用户能自己看出「抓到了什么」

「做的是单指、界面显示握拳」这种问题光看画面分不出来（手指没读到？判据认错？
还是姿势没抓准？）。所以录制弹窗多显示一行 **`_hand_shape_text()`**：
这一帧识别到的手型（`current_hand_shapes()`）+ 逐指弯曲度（来自姿势快照）。

配套：状态行 `hands_status_label` 的文字来自 `_hands_summary(present)`，它只报
**这一帧**的结果；判不出手势时写「已检测（手型未识别）」，不能回退成上次触发的
手势名（那就是「一直做单指、界面一直显示握拳」的来源）。

⚠️ **改完这一块，用户之前录的姿势模板要删掉重录**：老模板是用被投影压平的
弯曲度存下来的（单指的食指可能记成了 1.0），旧值配新度量仍然分不开。
